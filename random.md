Task 1 — Load the blank template (the second parse pass)
Right now you parse the client PDF. Now you also need to open and read the blank seller-report template — the empty Excel with the yellow cells. The agent should write the loader that opens that template and walks it. For each field it finds, it needs to pull out three things: the field's label, the cell it lives in (like input!B34), and any format hints. This is the same "read a document and get fields out" job you already do for the PDF, just pointed at the template instead. Start with the static templates Chander gave you; the API to fetch them live comes later.
Task 2 — Handle Excel as an input, not just PDF
Some sellers send the report as Excel, not PDF. So the input side of your parser needs to accept Excel (and JPS) and produce the same field list you'd get from a PDF. The agent should test this against the Excel samples Chander's sending, and flag anything that breaks or looks off. You already support it — this is mostly making sure it actually holds up.
Task 3 — Build the matcher between the two field lists
This is the heart of it. You now have two lists: maybe 200 attributes out of the client PDF, and maybe 70 out of your template. The agent builds the model that looks at both and says, "this PDF field probably maps to this template cell," with a confidence score for each guess. High score, you auto-fill the cell. Low score, you leave it for the human to decide. This replaces the hand-written mappings entirely.
Task 4 — Wire the confidence into the fill logic
Once you have a match score, the agent writes the rule: above the threshold, copy the PDF value straight into the template cell. Below it, don't guess — hold it and mark it for the person to confirm, clone, or skip. Extracted fields that have no matching template cell just get dropped quietly, because the PDF is a superset and we only care about our ~20 fields.
Task 5 — Keep all the math out of your code
Important guardrail: your backend fills the yellow cells and nothing else. No calculations, no aggregations, no rolling averages. The Excel's own macros do all that. The agent should treat the macros as untouched and even lean on them as a validation check after filling. If the LLM starts doing arithmetic, that's a bug, not a feature.
Task 6 — Pull prior months only when a field needs it
A few fields need last month's numbers (like a 3-month average). Those come from the filled-in prior templates on the NAS. The agent should only reach for those when a field actually depends on history — most values come fresh from this month's PDF, so this is a small, occasional lookup, not a big pipeline.
Task 7 — Let it run ahead of the user
Files often land overnight. The agent should make the pipeline able to pre-process a report the moment it arrives, so when the person shows up in the morning, the results are already sitting there waiting. They review, they don't wait.
